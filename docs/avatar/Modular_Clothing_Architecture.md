# Modular Clothing Architecture

## Philosophy
Clothing must remain easy to change without rebuilding the avatar. Do not permanently remove the base body, and do not divide the visible body into crude interchangeable blocks that create visible seams. Use modular slots and hidden-body masks while preserving a seamless canonical body underneath.

## Supported Garment Types
- Shirts, Jackets, Pants, Skirts, Dresses
- Boots, Shoes, Gloves
- Armor, Helmets, Belts, Holsters, Accessories

## Technical Implementation
- **Skinning**: Use separately skinned clothing meshes where appropriate.
- **Masking**: Support body-region masking underneath clothing to prevent skin clipping during extreme deformation.
- **Modularity**: Garments attach to predefined semantic slots (e.g., `Torso_Outer`, `Legs_Inner`).

## Required Clothing Metadata
Every piece of clothing generated by the Clothing Forge must include the following metadata package before attaching to the avatar:
1. `Compatible body` (e.g., Male_Standard_V1)
2. `Clothing slot` (e.g., Upper_Body_Layer_2)
3. `Covered body regions` (List of body vertices/faces to be masked)
4. `Skinning profile` (Weight maps bound to the Canonical Rig)
5. `Cloth behavior` (Physics constraints, stiffness, weight)
6. `Collision profile` (Interaction with body colliders)
7. `Material slots`
8. `LODs` (Levels of Detail matching the body)
9. `Penetration-test status` (Boolean: Passed/Failed)
10. `Export compatibility` (List of target platforms)
