# Titan Clean-Room Protocol

**Phase 5: Clean-Room Protocol**

Any component classified as a `CLEAN_ROOM_REIMPLEMENTATION_CANDIDATE` (e.g., PRNet architecture, FaceNet architecture) must follow this strict engineering protocol before it can be committed to the production Viper Studios environment.

### 1. Behavior-Level Specification
Before writing code, an engineer must draft a specification based EXCLUSIVELY on:
* The published academic paper (e.g., "Joint 3D Face Reconstruction and Dense Alignment with Position Map Regression Network").
* Public mathematical descriptions (e.g., PyTorch standard library definitions for ResNet blocks).
* Observable inputs and outputs (e.g., Input: 256x256 RGB, Output: 256x256x3 Position Map).
* Benchmark behavior (e.g., matching the `GB001` test matrix).

### 2. Prohibited Materials
The specification and subsequent implementation MUST EXCLUDE:
* Source-code excerpts copied from the original restricted repositories.
* Distinctive function, class, or variable names unique to the restricted implementation.
* Line-by-line translations from TensorFlow to PyTorch or vice-versa.
* Internal magic constants or hyperparameters copied without independent derivation or justification from the academic paper.

### 3. Implementation Requirements
The Titan-owned clean-room implementation must:
* Use entirely new module and directory names (e.g., `TitanUVRegress` instead of `PRN`).
* Use independently designed data structures and interfaces (conforming to Phase 4 provider interfaces).
* Use independently written unit tests.
* Document the mathematical formulas and cite the academic paper in the docstrings to establish provenance.
* Be trained ONLY on commercially licensed datasets or synthetic data generated by Viper Studios. **UNDER NO CIRCUMSTANCES** may `300W-LP`, `VGGFace2`, or the provided open-source `.pt` weights be loaded into the production training script.

### 4. Enforcement
Restricted implementations may remain in `services/project-titan-3d/local-compute-node/` ONLY for isolated research and benchmarking. They must never be imported by `Headquarters` or `AvatarForge`.
